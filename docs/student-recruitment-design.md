# Student Internship Recruitment

Product/user: students finding internships offered by approved Industry Partners.
Surface: Operate. Primary task: find a suitable internship, read details, apply through the existing application dialog.
Direction: JobStreet-inspired keyword/location search and job-list/detail reading flow, with RTU navy, blue interactions, gold focus, Inter and existing cards. No copied brand assets.
Hierarchy: search first; results and course filters next; title/company/location in each result; detail header with eligibility and Apply action; responsibilities, skills and company below.
Content: published jobs, approved companies, course eligibility, actual locations/industries, openings, description, skills, posting dates and existing application state. No invented salaries, saved jobs or job alerts.
States: no posts; no matches with clear/reset; selected detail; applied; ineligible with reason; missing metadata fallbacks; phone list/detail navigation. Keep staff surfaces and application actions unchanged.
Controls: explicit keyword/location search, program/industry filters, course-only toggle, newest/oldest sorting; query parameters retain browsing state. Phone uses a dedicated details view with Back to Results. No nested scrolling on phones.
Out of scope: posting workflow, backend matching, application sharing rules, company moderation.
