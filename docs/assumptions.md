# Assumptions and runtime boundaries

## Visual theme

The demo uses a blue-and-gold palette and diagonal band motif inspired by Rizal Technological University's public [gold-and-blue language](https://www.rtu.edu.ph/wp-content/uploads/2025/07/APRIL-2025-Diario-Rizalia.pdf), [Pandayang Rizalia ethos](https://www.rtu.edu.ph/about/), and [academic sablay](https://www.rtu.edu.ph/rtu-debuts-sablay-in-its-52nd-commencement-exercises/). The interface colors are design approximations; no official color specifications or seal usage is claimed. Rizal Technological University, its people, policies, and records remain fictional demo content.

Confirmed product requirements remain in build-brief.md. One university is a tenant; departments and courses are separate. Classes are section/period scoped. Student progress is self-reported until its complete final DTR is verified by the assigned approved HTE; completion is a separate coordinator decision. Supervisor policy scope is explicit and company verification does not confer global access. Policy targets are placement snapshots. Identified SOS cases are visible only to their reporter and class coordinator; Super Admin and supervisors cannot read narratives.

External HTE users have a separate limited portal. A company profile requires university verification; each internship post requires approval before students can see it. An HTE may shortlist or decline applicants to its own posts, while a coordinator confirms and later activates the placement. HTEs can verify the complete submitted DTR time only and cannot read narratives, documents, SOS cases, rosters, analytics, or university administration. A host without an account has no company profile or posting access: the coordinator stores host contact details privately and issues a one-use, expiring evaluation link with a separate access code. The code is required before the form reveals the student identity. Student company feedback is identifiable to authorized university staff and anonymous to the HTE until at least five approved reviews from distinct placements exist in the same academic period. The final competency self-assessment and OJT program exit survey are separate; both unlock at the reported-hour target, and neither automatically approves completion.

All demo names, companies, hours, rubric scales, documents, reviews, and university identity are fictional. Demo course targets are 480 hours IT and 400 hours Business/Education; these are never represented as university requirements. The synthetic framework uses 1–5 solely for demonstration. Document metadata describes labeled samples and does not imply a real medical clearance. Unknown production rules block dependent work.

## Stack and architecture decision

UI: Next.js App Router/React 19, TypeScript strict, Tailwind 4, Shadcn primitives, Lucide, Recharts, React Hook Form/Zod. Development now uses native Next.js on the Node.js runtime, with Vercel as the chosen deployment target.

Database: PostgreSQL 17 with Prisma 6.19.3, committed migrations, and a local Docker service on port 5433. A dedicated hosted PostgreSQL database for Vercel Preview still needs to be configured. The present fictional demo uses the reduced demo table shape in PostgreSQL through a Prisma-backed, parameterized compatibility layer; the normalized 68-model institutional schema is preserved. Live migration and workflow verification are recorded in `validation.md`.

Demo boundary: the active local app uses a PostgreSQL database dedicated to fictional data. `DEPLOYMENT_MODE=demo` and `DEMO_ENABLED=true` are required; seed checks that the fixed demo tenant is in `DEMO` mode. Keep any institutional database on a separate connection and deployment. The existing hosted Cloudflare demo remains the rollback path until the Vercel preview has passed sign-in and role-scoped workflow checks. No real institutional records belong in this demo.

Authentication uses Auth.js @auth/core 0.41.3 with JWT sessions; credentials require JWT (not database sessions). This is the maintained core package, marked experimental by its upstream docs. Registry next-auth v5 is 5.0.0-beta.32 (prerelease); we use core directly with standard Request/Response route handlers, not an invented v5 API. Each protected operation reloads the active account and session version. Demo role selection maps only to four fixed seeded demo IDs, never arbitrary roles. Username/password uses Node-compatible OpenSSL PBKDF2-SHA256, 600,000 iterations, random 16-byte salts, constant-time hash comparison. Auth.js CSRF remains enabled. Google is visibly unavailable until credentials, verified-domain allowlist, provisioned-account matching and deliberate linking are configured.

## Services and limitations

Google, Resend, malware scanning, durable export queue, password recovery, initial real admin bootstrap and formal completion rules are not configured. The Word generator stores tenant-scoped template versions and student drafts; generated files retain the original Word layout. Private document storage and scanning are not configured. Generated files do not collect signatures, establish legal consent, or issue clearance. No official seal, institutional policy, or template content is fabricated.

Demo state is durable in the separate PostgreSQL demo database. Changes are shared by four fixed quick demo identities, including the limited-access HTE Supervisor; the HTE account also supports the normal username/password form. Seed is idempotent; it does not reset existing demo edits. Demo accounts cannot be deactivated or reassigned through the demo UI. Institutions must use a separate deployment/database and set `DEPLOYMENT_MODE=institutional`, `DEMO_ENABLED=false`. This application refuses institutional mode rather than bypassing missing authorization.

The HTE registration, business-approval, final DTR and school-evaluation decisions in `../PRODUCT.md` supersede the previous daily confirmation and sample HTE rubric behavior. Formal completion requires verified final attendance and an approved school HTE evaluation in addition to both student exit forms. The real school document is not supplied yet; the evaluation intentionally remains waiting for Super Admin upload and publication.
